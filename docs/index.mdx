MCPJungle aggregates multiple MCP servers into a single MCP endpoint.

It acts as a gateway that your AI clients connect to, providing unified access to tools, prompts, and resources across all MCP servers.

## Why MCPJungle?

Without a gateway, MCP usage does not scale cleanly. Every new MCP server means more duplicated client config, more scattered credentials, and less visibility into what tools are actually available.

MCPJungle introduces a single control layer for that sprawl.

<CardGroup cols={2}>
  <Card title="One endpoint for everything" icon="network-wired">
    Register any number of MCP servers. Every AI agent connects to a single `/mcp` endpoint and gets access to all tools automatically.

  <Card title="Streamable HTTP and STDIO support" icon="arrows-left-right">

## Get started in 3 steps

<Steps>
  <Step title="Start the server">
    Pull the Docker Compose file and start MCPJungle with a persistent Postgres database:

    ```bash
    curl -O https://raw.githubusercontent.com/mcpjungle/MCPJungle/refs/heads/main/docker-compose.yaml
    docker compose up -d
    ```
  </Step>
  <Step title="Register an MCP server">
    Use the CLI to add your first MCP server. This example uses [context7](https://context7.com/):

    ```bash
    mcpjungle register --name context7 --url https://mcp.context7.com/mcp
    ```
  </Step>
  <Step title="Connect your AI client">
    Point your MCP client at the MCPJungle gateway. For Claude Desktop:

    ```json
    {
      "mcpServers": {
        "mcpjungle": {
          "command": "npx",
          "args": ["mcp-remote", "http://localhost:8080/mcp", "--allow-http"]
        }
      }
    }
    ```
  </Step>
</Steps>
