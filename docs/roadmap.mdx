This roadmap explains where mcpjungle is heading over the next few months.

In short, our focus is to:

1. Keep mcpjungle extremely simple & useful for developers
2. Remove the biggest blockers to real MCP usage
3. Add collaborative capabilities for teams

# Here's what's coming next

## 1. Oauth Support

This is the highest-priority area.

We are working on:

- OAuth support for both upstream MCP servers and downstream clients
- smoother handling of stored credentials and token refresh flows
- integration with OpenID Connect

## 2. Better configuration-driven workflows, Infrastructure as Code, and GitOps support

We want mcpjungle to be easier to operate repeatedly, not just easy to try once.

We are working on:

- declarative configuration for managed entities
- config-driven reconciliation at startup
- live reload for supported config changes
- a more GitOps-friendly workflow for operators managing shared setups

## 3. A Web GUI ✅ Shipped in v0.1.0

The Management Dashboard is live. Start with `mcpjungle start --enterprise --ui`.

The dashboard covers:

- Server, tool, and tool-group management
- MCP client token CRUD with per-client allow-lists
- User management with per-user server access control
- **Groups** — assign users to groups and inherit access at team scale
- Self-service token creation from the Settings page
- One-click **Apply Config** for Claude, Cursor, Codex, Copilot, OpenCode, and Zed

## 4. Better access control in enterprise mode ✅ Partially shipped in v0.1.0

Per-user and group-level server allow-lists are now available in the dashboard.

Remaining items:

- per-client credentials (OAuth / OIDC)
- more fine-grained ACLs (tool-level access per user or group)
- audit log for access events

# How we make roadmap decisions

We use a simple prioritization model:

1. Unblock real usage
2. Reduce setup and operational friction
3. Improve visibility
4. Add focused control where teams actually need it
