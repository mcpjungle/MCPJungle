MCPJungle is an open-source, self-hosted gateway for [Model Context Protocol](https://modelcontextprotocol.io/introduction) servers.

Instead of configuring every AI client to connect to each MCP server separately, you register those servers once in MCPJungle and expose them through a single `/mcp` endpoint.

MCPJungle is especially well suited to two usage patterns:

- Individuals running MCPs locally for personal workflows
- Teams running MCPJungle as shared infrastructure with centralized management and collaborative control

## The problem MCPJungle solves

As MCP usage grows, the management overhead compounds quickly:

- Every new MCP server has to be configured in every client.
- Credentials and headers are duplicated across tools and environments.
- Tool discovery becomes fragmented across many server endpoints.
- Teams lose a clean place to apply access control and observability.

MCPJungle centralizes that sprawl. You register servers once, keep one gateway endpoint in front of them, and let AI clients discover tools through that single connection point.

## How it works

MCPJungle has a client-server architecture:

- **Gateway server**: Runs as an HTTP service on port `8080` by default. It stores registered MCP servers, proxies calls to them, and exposes a unified streamable HTTP MCP endpoint at `/mcp`.
- **CLI client**: The `mcpjungle` binary you install locally. Use it to register servers, inspect tools, create tool groups, initialize enterprise mode, and manage access.

The gateway supports both [streamable HTTP](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports#streamable-http) and [stdio](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports#stdio) MCP servers. Clients connect only to MCPJungle. MCPJungle handles the rest.

## Who should use MCPJungle?

- **Individual developers** who want Claude Desktop, Cursor, or Copilot to share one MCP setup instead of many.
- **Teams building AI agents** that need a stable tool gateway with centralized registration and curation.
- **Organizations** that need self-hosted access control, audit-friendly operations, and no dependency on a third-party MCP aggregator.

## Deployment modes

MCPJungle supports two operating modes:

- **Development mode**: Ideal for local use by an individual. No gateway authentication is enforced.
- **Enterprise mode**: Designed for shared deployments. It enables authenticated access, per-client server allow-lists, and OpenTelemetry metrics by default.

That split makes it workable for both a solo developer on a laptop and a small or mid-sized team running a shared MCP control plane.
