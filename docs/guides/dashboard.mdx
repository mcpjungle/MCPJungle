# MCPJungle local dashboard

The MCPJungle dashboard is a lightweight, local-first web UI for developers running MCPJungle on their own machine.

It is intentionally narrow in scope:

- It is **not** an enterprise admin portal
- It is **not** a SaaS dashboard
- It is **not** a replacement for the CLI on day one
- It is a local-first v1 surface focused on the most useful developer workflows

## Who it is for

The dashboard is built for an individual developer who wants to answer a few questions quickly:

1. Is MCPJungle running?
2. Which MCP servers are registered?
3. Which tools, prompts, and resources are currently available?
4. Which tool groups are configured?
5. Which endpoint should my MCP client connect to?

## How to access it

Start MCPJungle in development mode:

```bash
mcpjungle start
```

Then open:

```text
http://localhost:8080/
```

The dashboard is only available in **development/local mode**.

If the server is started in enterprise mode:

```bash
mcpjungle start --enterprise
```

the root dashboard route is not exposed. MCPJungle returns `404` for the dashboard surface and its internal dashboard API routes in enterprise mode.

## What the dashboard shows

### Servers

- Registered MCP servers
- Transport type
- Tool, prompt, and resource counts
- Safe connection summary without secrets
- Expandable per-server details
- Add server
- Delete server
- Enable/disable server
- Upstream OAuth registration flow when required

### Tools

- Tool name
- Canonical MCPJungle name
- Source server
- Description
- Human-readable input fields in expandable rows
- Client-side search/filter
- Enable/disable tool

### Tool Groups

- Configured tool groups
- Create tool group
- Delete tool group
- Expandable per-group details
- Copy group MCP endpoints

### Prompts

- Prompt name
- Canonical MCPJungle name
- Source server
- Description
- Human-readable arguments in expandable rows
- Client-side search/filter
- Enable/disable prompt

### Resources

- Resource name and URI
- Source server
- MIME type
- Description
- Copy resource URI

### System Info

- Server version
- Runtime mode
- Database type
- Enabled transports
- Global MCP endpoint

## Security and limitations

- It is **not exposed in enterprise mode**
- It does **not** expose bearer tokens, OAuth credentials, authorization headers, environment variable values, or other raw secrets
- It does not replace enterprise admin workflows, access control workflows, or the existing CLI

## Development notes

The dashboard frontend lives under [`web/dashboard`](</Users/raghav/Desktop/code/MCPJungle/web/dashboard>).

Use the frontend dev server for iterative UI work:

```bash
cd web/dashboard
npm install
npm run dev
```

The Vite dev server proxies `/api/*` requests to the Go server on `http://localhost:8080`.

To produce the embedded UI bundle:

```bash
cd web/dashboard
npm run build
cd ../..
rm -rf internal/dashboardui/dist
cp -R web/dashboard/dist internal/dashboardui/dist
```

The Go server serves the built assets from the embedded bundle in [`internal/dashboardui`](</Users/raghav/Desktop/code/MCPJungle/internal/dashboardui>).

That means normal MCPJungle usage does **not** require a separate frontend dev server after the dashboard assets are built and embedded.

For the full frontend architecture, dashboard API, build workflow, and troubleshooting guide, see [Dashboard frontend development](/dashboard-development).
